# Portcullis v0.1 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a runnable, tested v0.1 MCP gateway with registry management, API-key authentication, default-deny RBAC, Redis rate limiting, and stateless Streamable HTTP proxying.

**Architecture:** Build five ordered vertical slices. FastAPI routes call services, services depend on repository/infrastructure protocols, PostgreSQL stores control-plane state, and Redis performs atomic enforcement. Every behavior begins with a failing test and is committed after focused and regression checks pass.

**Tech Stack:** Python 3.12, FastAPI, Pydantic Settings, SQLAlchemy 2 async, asyncpg, Alembic, Redis, httpx, Argon2id, pytest, Hypothesis, testcontainers, Ruff, mypy, Docker Compose

**Design:** `docs/superpowers/specs/2026-08-03-v0-1-mvp-design.md`

---

## Release Sequence

1. Foundation and registry: Tasks 1-6.
2. API-key authentication: Tasks 7-8.
3. RBAC: Tasks 9-10.
4. Redis rate limiting: Tasks 11-12.
5. MCP proxy and release verification: Tasks 13-15.

Each task ends with a focused commit. Existing working-tree deletions outside this feature are never staged.

## Final Review Checklist

- Every approved design section maps to at least one task.
- OAuth, persistent audits, OpenTelemetry, Prometheus, sessions, admin UI, SaaS tenancy, stdio bridging, and Helm remain absent.
- No API route returns ORM entities.
- No response or log exposes keys, peppers, upstream tokens, or full tool arguments.
- Admin scope never bypasses tool RBAC.
- Redis and registry infrastructure failures fail closed.
- Each commit stages only its owned paths.
